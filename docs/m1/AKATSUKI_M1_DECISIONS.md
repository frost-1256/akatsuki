# Akatsuki M1 — 未決事項 5 点の決定

2026-11-07 決定（はるの始動決定＋入り方「未決を全部潰してから」に基づく机上決定）。対象は `AKATSUKI_M1_SCOPE.md` の未決事項 1〜5。各項は「決定／根拠／見直し条件」の形で固定する。ここに書かれた決定は M1a の設計前提であり、実機で反証が出たらこの文書を更新して覆す。

## 1. バインド先 ACPI ノード → GPU0 流用（HID 差し替え）

**決定**: 既存の GPU0 を流用する。GPU0 の `_HID`（現在 `QCOM0A36`）を自作用の新規 ID に差し替え、Epinephrine の INF をその ID にマッチさせる。`_CRS`（表示系・グラフィックス系・ビデオ系の全リソース）、`_DEP`（現行 8 件）、`_ROM`（PCFG パネル XML）、子 `MON0`、`_DOD` はそのまま使う。詳細検討は `AKATSUKI_M1_ACPI_NODE.md`（本決定で採用済み）。

**根拠**:
- 差分が最小で、EDID 合成の土台（PCFG）が無傷で残る。表示専用新ノード（B 案）は MMIO 窓の二重主張と PCFG コピーの乖離という、本線で実際に踏んだ罠を自ら作る
- 公式ドライバのバインドは HID マッチ（`ACPI\VEN_QCOM&DEV_0A36`）なので、HID を替えれば排他は構造的に成立する。併せて公式側は ConfigFlags で無効化し、二重担保にする
- M1a〜M1b はテストパターンまで GPU シェーダ不要なので、`_DEP` に PILC／TREE が無い現状はむしろ都合がいい

**見直し条件**: GFX／VIDEO 系リソースを引き受けることが実害になったら B 案（表示専用ノード）に移行する。DSDT 変更は DSL と AML の両方をコミットする（出荷フローの既存規則）。

## 2. フレームバッファの置き場所 → SMMU 変換経由の通常メモリ

**決定**: フレームバッファは通常ページ（非連続）で確保し、自ドライバの SMMU コンテキストにマッピングして、表示パイプラインには I/O 仮想アドレスで渡す。書式は 1080×2400・32bpp（XRGB8888）、1 面 10,368,000 バイト、M1c 以降は 2 面。SMMU コンテキストの設計値はスコープの規則どおり **PTM=1**（DVM 参加オフ）。

**根拠**:
- 物理連続メモリの大量確保（2 面で約 20MB）は断片化で実行時に失敗しうるし、本線の凍結解析で「連続確保＋バリア待ち」のスタックが震源付近に繰り返し現れた経路に近い。通常ページ＋SMMU 変換なら確保は堅牢で、凍結機構（ブロードキャスト TLB 無効化への参加）も PTM=1 で設計から外せる
- 表示ブロックは SM7325 上で SMMU 配下にあり、公式スタックも表示バッファを SMMU 変換経由で流している。通常メモリ方式はプラットフォームの想定内
- Present の受け取り（OS のソフトウェア合成からのコピー）は CPU アクセス可能な通常ページが前提で、KMDOD 型ドライバの標準形でもある

**見直し条件**: 表示パイプラインの特定段（回転・フェッチ等）が物理連続を要求すると実機で判明したら、その段だけ DMA 共通バッファ（連続）確保に切り替える。設計の対外インターフェース（IOVA で渡す）は変えない。

## 3. 圧縮の初期値 → DSC オンを正とする

**決定**: M1b の最初の点灯から **DSC オン**。パラメータは確定済みの完全一致セット（DSC 1.1、スライス 540×20、色深度 10、8 bpp、PPS はメインライン採取値）を使い、送信順序もメインラインの最終形（表示オン完了 → PPS → 圧縮モード → 28ms 待機）に従う。無圧縮は M1c で A/B 実験として可否を確定する対象に回す。

**根拠**:
- DSC パラメータは本線調査でデバイスツリーとバイト単位の一致まで照合済みの「閉じた」領域。M1b（最初の正しい絵）の成否を、未証明の要素に賭けない
- パネル側の無圧縮受信は本線でも未証明（dsc0 実験はホスト側送信までで、パネルが無圧縮で受けたかは確定していない）
- 帯域の見積もりでも無圧縮は苦しい: 1080×2400・24bpp は 60Hz で約 3.7 Gbit/s、120Hz では約 7.5 Gbit/s（いずれもブランキング抜き）。4 レーン DSI の実効帯域では 120Hz 無圧縮は成立が怪しく、既知の正常系は全て DSC 前提

**見直し条件**: M1c の A/B でパネルの無圧縮受信が証明されたら、無圧縮をデバッグ用の逃げ道として正式に採用する（正は DSC のまま）。

## 4. 表示専用モデルの世代 → KMDOD 系（WDK サンプル土台）

**決定**: Windows 11 22H2 の表示専用ドライバとして、**Kernel Mode Display-Only Driver（KMDOD）モデル**を採用する。土台は WDK サンプルの KMDOD。登録は display-only 用の初期化経路（DxgkInitializeDisplayOnlyDriver）で行い、実装する DDI は表示専用の集合に限る：デバイス追加／開始／停止／削除、QueryAdapterInfo、子デバイス関係・状態・記述子（EDID は PCFG 由来）、電源状態、PresentDisplayOnly、割り込み（VSYNC＝GPU0 `_CRS` の IRQ 0x73）とその制御、GetScanLine、自前診断用の Ioctl、Unload。レンダリング系 DDI は実装しない。INF は Display クラス、自作 ACPI HID にマッチ（決定 1）。

**根拠**:
- 22H2（WDDM 3.0 世代）でも display-only モデルは正式に使える経路で、Microsoft Basic Display Adapter と同じ型。OS 側ソフトウェア合成＋ PresentDisplayOnly でデスクトップまで届くことがモデルの前提になっており、M1a〜M1d の段階定義と一致する
- フル WDDM ミニポートはレンダリング前提の DDI 契約（メモリ管理、アロケーション、パッチ等）が重く、M1 の範囲（モード設定とスキャンアウトだけ）に対して過大
- サンプル土台があることで、骨格（M1a）の工数は VidPn や子列挙の定型に溶かせる

**見直し条件**: M2（最小レンダリング）に入る時点でフル WDDM への移行を再評価する。M1 の間は display-only で固定。

## 5. クロックと電源の要求経路 → PoFx 正規登録＋ PEP0 側 COMPONENT エントリ

**決定**: 2 段構えで固定する。

1. **ドライバ側**: Epinephrine は Windows の電源フレームワーク（PoFx）に正規登録する。コンポーネントは表示系を単位に切る（表示コア系クロック、DSI 系クロックを想定）し、F 状態をクロック水準に対応させる。デバイスの D 状態遷移は `_DEP` 先行（PEP0 を含む現行 8 件を維持）とセットで扱い、レールやクロックをモデルの外から直接叩かない（スコープの設計規則そのまま）
2. **プラットフォーム側**: PEP0 の `Device Parameters\Resources` レジストリに、自デバイス向けの **COMPONENT レコード入り**エントリを用意する。qcpep の RE 決着（2026-10-29）で、PEP のデバイスモデルはこのレジストリが正本であり、COMPONENT の無いエントリでは投票が消費されないことが最有力の読みだった。エントリの書式は、既に動いている他デバイスのエントリの形を正とし、M1a 立ち上げ時に実機の現行エントリを読んで写す

**根拠**:
- タッチの教訓（モデル未登録の電力要求は再計算で落とされる）と、ドライバ側の生レール叩きで SoC クリティカル障害を起こした事故の両方が、「モデルに登録して投票する」以外の経路を否定している
- 公式ドライバは自前の RPMh 投票機構を持つが、それは PEP 側に公式向けの登録が揃っている前提の実装で、自作側が真似る対象ではない。自作側は Windows 標準の PoFx 契約で参加するのが、PEP にとっての「正規の客」の形

**見直し条件**: PoFx 登録＋ COMPONENT エントリでも表示クロックが上がらない場合、その時点で初めて PEP のメソッド呼び出し（ACPI 経由のクロック要求）の要否を検討する。生レジスタ投票への後退はしない。

## 決定の相互関係

- 決定 1（GPU0 流用）により、決定 5 の `_DEP` は現行 8 件（PEP0 を含む）をそのまま使える
- 決定 2（SMMU 通常メモリ＋ PTM=1）と決定 5（PoFx 登録）は、スコープの設計規則 2 条を具体化したもの
- 決定 3（DSC オン）と決定 4（KMDOD）は M1b／M1d の完了条件に直結する
